# News Watch — UI/UX モダン化プラン

このディレクトリは News Watch のフロントエンド刷新プランを保管する。
実装前に `01` → `07` の順で読むことを想定している。

## 決定済みの前提（ユーザー確認済み）

| 項目               | 決定                                                             |
| ------------------ | ---------------------------------------------------------------- |
| コンポーネント基盤 | **shadcn/ui を導入**（Radix ベース、`new-york` スタイル）        |
| スコープ           | **体験の再設計まで含む**（見た目 + インタラクション + 情報設計） |
| テーマ             | **ライト/ダーク両対応 + 手動切替**（OS 設定追従をデフォルト）    |
| お気に入り機能     | **現状維持**（5 回タップの隠し機能を維持。明示 UI 化しない）     |

## 中心にある問題意識

現状は「Tailwind のユーティリティ文字列を各ファイルに直書きした画面が 3 つ、それぞれ独自の
シェルを持っている」状態で、共有された語彙が存在しない。結果として:

1. **同じ役割の UI が画面ごとに違う見た目になっている**（ボタンだけで 3 種類の実装）
2. **ダークモードが実質破綻している** — トークンは切り替わるがコンポーネントが白を直書き
3. **主要機能が隠し操作になっている** — お気に入り登録が「要約を 5 回タップ」でキーボード不可
   （ただしお気に入りは **現状維持が決定**。この欠陥は既知の制約として許容する）
4. **画面間の導線がない** — `/` から `/bookmarks` へのリンクが存在しない

このプランは「装飾を足す」のではなく、**共有トークンと primitive を先に作り、その上で
画面を組み直す**順序を取る。詳細は [07-roadmap.md](./07-roadmap.md) を参照。
